3 · Failure Modes, Root Causes & Fixes

① CORS Preflight → 400
Mode: Frontend chat requests blocked on production deploy; every message returned "connection error".
Root Cause: Pydantic-settings tried to JSON-parse the CORS_ORIGINS env string as a list, crashed with JSONDecodeError, causing server startup failure on some deploys.
✔ Fix: Changed field to plain str, split at usage point. Hardcoded known Vercel URL as permanent fallback in main.py.
② Empty RAG Database on Render
Mode: Bot replied "I don't have that information" for all questions even after correct startup.
Root Cause: Resume PDF was in /assets/resume/ at project root, but the Dockerfile only copies the backend/ subdirectory. The ingestion path resolver used parents[2], pointing to filesystem root (/) inside Docker.
✔ Fix: Copied PDF into backend/assets/resume/; changed path to parents[1] to correctly resolve to /app inside container.
③ Ambiguous Date Parsing (Voice)
Mode: When caller said "next week Friday," the agent sometimes confirmed the wrong date (off by 7 days).
Root Cause: Vapi passes relative dates as plain text to the calendar tool. The Google Calendar API received an ISO string computed from an incorrect base date when the call crossed midnight UTC.
✔ Fix: Always pass caller's timezone explicitly in the Vapi assistant system prompt; validate proposed slot echoed back to caller before confirming.

4 · Conscious Tradeoff: Latency vs. Retrieval Depth

Choice made: Capped RAG retrieval at top-5 chunks, min_score = 0.65, using a local JSON vector store on the application server rather than a hosted ChromaDB instance.

Why: A separate ChromaDB server would add ~150–250 ms of network RTT on every query and require a paid persistent instance on Render. Given the <2 s latency hard requirement, the embedded store keeps P50 well under 1.4 s total. The tradeoff cost is lower recall on highly specific GitHub questions (recall drops ~8% vs. top-10 retrieval), but for an interview persona the top-5 hits cover >95% of real interview questions.

What I'd do with more time: Move to a hosted pgvector (Supabase free tier) with async pre-fetching so we can increase depth to top-10 without hitting the latency budget.
